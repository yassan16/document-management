# 月次課題記録テンプレート

## 概要

プロジェクト参画中に発生した課題を月ごとに記録し、原因・改善策・次の行動の観点で整理するためのテンプレートです。
日々の問題を単なる反省で終わらせず、次回の判断基準や作業プロセスの改善に変換することを目的とします。

## 記録ルール

- 1日につき、最も改善効果が高い課題を1つだけ記録する
- 起きた事実と、事実から判断した問題や影響を分けて書く
- 短文で要点を押さえて記載する
- 個人の注意不足で終わらせず、判断基準や仕組みに落とす
- 人ではなく、状況・判断・プロセス・情報の流れに着目する
- 次のアクションは、具体的に実行できる内容にする
- 月末に記録を見返し、繰り返し発生した課題と改善できた点を整理する

## 記録する観点

日次記録は、情報を一覧しやすくするため、次の5つの観点を表形式で記録します。

| 観点 | 定義 |
| --- | --- |
| 起きたこと | 実際に観測または確認できた出来事や状況。推測や評価は含めない |
| 問題・影響 | 起きたことによって生じている現在の支障と、将来起こり得る結果やリスク |
| 原因 | 問題が発生した背景にある判断、プロセス、情報共有、仕組み上の要因 |
| 改善策 | 同じ問題を防ぐために、次回から適用する判断基準や継続的な仕組み |
| 次のアクション | 改善策を実現するために、次に着手する具体的な行動 |

「起きたこと」には観測できる事実を記載し、「問題・影響」にはその事実によって生じている支障やリスクを記載します。
「改善策」は今後も適用する判断基準や仕組みを表し、「次のアクション」は改善策を実現するために次に行う具体的な一歩を表します。

## 月次ファイルの作り方

1. 月初にこのテンプレートをコピーし、`YYYY-MM.md` 形式で保存する
2. `# YYYY年M月 日次課題記録` の年月を対象月に変更する
3. 日々の記録は `日次記録` セクションに日付と課題を見出しとして追記する
4. 月末に `月次振り返り` を記入する

## 記入例

```markdown
# 2026年7月 日次課題記録

## 概要

2026年7月の業務中に発生した課題を1日1点記録し、原因・改善策・次の行動の観点で整理します。

## 目次

- [日次記録](#日次記録)
- [月次振り返り](#月次振り返り)
- [参考](#参考)

## 日次記録

### 2026-07-09：仕様の前提確認不足による手戻り

| 観点 | 内容 |
| --- | --- |
| 起きたこと | 既存仕様の確認が不十分な状態で修正方針を決めた。レビュー時に想定していなかった利用ケースを指摘され、実装の一部をやり直した |
| 問題・影響 | 実装の手戻りによって予定外の工数が発生し、後続作業の開始が遅れた。同じ進め方を続けると、納期や品質へ影響する可能性がある |
| 原因 | 作業前に確認すべき仕様、画面、関連コードを洗い出していなかった。不明点を質問する前に、自分の前提を明文化していなかった |
| 改善策 | 仕様が不明なまま実装に入らない。作業開始前に「目的 / 影響範囲 / 不明点」を整理し、15分調べても判断できない場合は調査内容と仮説をまとめて相談する |
| 次のアクション | 作業前メモのテンプレートを作り、PR作成前チェックリストに仕様確認の項目を追加する |

## 月次振り返り

### 繰り返し発生した課題

- 仕様の前提確認が不十分なまま作業に入ることがあった

### 改善できたこと

- 作業前に目的と影響範囲をメモする習慣を作れた

### 来月の重点改善テーマ

- 実装前に不明点と確認先を整理してから着手する

## 参考

- [実務経験・振り返り](./README.md)
```
